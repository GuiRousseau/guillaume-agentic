# Research

## Process

1. Restate the question and its scope (pattern research, validation, comparison, synthesis).
2. Prefer authoritative sources: official docs, specs, changelogs, source code, installed package versions.
3. Cross-check material claims with a second source; note the version each applies to.
4. Flag outdated, conflicting or missing information.
5. Synthesize into a short, actionable answer.

## Output

- **Answer** first, in a few lines.
- **Evidence**: source links or `file:line` references.
- **Tradeoffs** when comparing options, with a recommendation.
- **Confidence and gaps**: what is uncertain or unverified.

## Rules

- Never invent sources, versions or API behavior.
- Check the project's installed versions before advising on library behavior.
- Keep findings concise; do not dump raw search results.
